# Routing AI coding tools through the gateway

Checked 2026-10-03 against official docs (sources at the end). **[?]** marks what we could not confirm in first-party docs.

**Where we stand:** the gateway speaks OpenAI `/v1/chat/completions` (upstream called with `stream: false`, reply sent as one SSE chunk), Anthropic Messages (`/v1/messages` with a real SSE relay checked per content block, `count_tokens`, `HEAD /api/hello`; a gateway-held org key or seat pass-through with `x-acl-key`) and MCP JSON-RPC at `/mcp/<server>`. Setup bundles live in `integrations/claude-code` and `integrations/coding-agents.md`. It has no OpenAI Responses endpoint.

## Recommended plan

1. **Claude Code first, with an Anthropic Messages endpoint** (~2-3 days). Most of the value and most of the work.
   - `POST /v1/messages`: forward `anthropic-*` headers and unknown body fields verbatim. Pass `count_tokens` through, answer `HEAD /api/hello`, and serve `/v1/models` if we want model discovery.
   - Two auth modes:
     - Gateway-held Console key: the employee's key goes in `ANTHROPIC_AUTH_TOKEN`.
     - Seat pass-through: forward `Authorization` and the OAuth `anthropic-beta` value untouched and never log either. Identity comes from `ANTHROPIC_CUSTOM_HEADERS: x-acl-key: <key>`.
     - Both ship as one managed-settings file: `env` + `allowedProviders: ["customEndpoint"]` + `allowManagedHooksOnly` / `allowManagedMcpServersOnly`. Whether `allowedProviders` accepts seat OAuth sent to a custom endpoint is unverified [?].
   - Inspection maps onto what we already do: `text` blocks are prompts, `tool_use.input` goes to tool RBAC, `tool_result` content is indirect-injection input, `tools[]` gets the poisoned-description checks. Claude Code resends the whole history every turn, so only check new content and cache verdicts by hash.
   - Don't rewrite history. Rewriting earlier `system`/`tools`/`messages` breaks prompt caching and thinking signatures (`bound to a different conversation`). Redaction has to be deterministic across turns, or limited to the newest turn.
   - Real SSE relay: stream text with a short hold-back window for the regex checks. Buffer each `tool_use` block until `content_block_stop`, check it, then release or withhold it. Keep forwarding `ping`s, because the client aborts after 5 min without bytes. On a block, end with `message_delta` (`stop_reason`) + `message_stop`, since a stream that just stops counts as a dropped connection and is retried. Pass error bodies, `retry-after`, `x-should-retry` and `anthropic-ratelimit-unified-*` through unchanged.
   - Log `x-claude-code-session-id` and the agent-id headers. Turn on `CLAUDE_CODE_GATEWAY_HINT_HEADERS=1` for request class and per-tool timings.
2. **OpenCode, Continue, Cline and Aider ride the existing endpoint** (~0.5 day). Ship a managed `opencode.json` (our provider only + MCP via `/mcp/*`). The real upstream streaming built for step 1 should also replace the single-chunk SSE on `/v1/chat/completions`.
3. **Cursor via hooks, not the base URL** (~1 day). A system-wide `hooks.json` whose script calls `/v1/guard` (deny on block), plus MCP through `/mcp/<server>`. The base-URL override would mean exposing the gateway to the internet and still misses Tab.

Later: pull the Claude Enterprise Compliance API and Claude Code OTel events into the audit log and risk scores (this covers seats we don't proxy). Add `/v1/responses` for Codex. Copilot only through the corporate TLS proxy, so out of scope for now.
